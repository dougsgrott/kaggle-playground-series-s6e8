# Playground Series S6E8 — Kaggle competition workspace

## What this is

A workspace for the Kaggle competition **Playground Series S6E8 — Predicting Smartphone
Addiction** (`playground-series-s6e8`), combining a generated knowledge base with the solution
code built from it. Binary classification of `addicted_label`, scored on **ROC-AUC**.
Final submission deadline **2026-08-31 23:59 UTC**. Reward is swag; Playground episodes award
no medals, so the goal here is the best expected **private**-leaderboard finish.

The knowledge base is produced by **kaggle-wiki-kit** ("wikikit"), installed as an editable
dependency from `../kaggle-wiki-kit`. One install serves every sibling competition folder — fix
pipeline bugs THERE, never by copying scripts into this folder.

Plan and status: [`docs/ROADMAP.md`](docs/ROADMAP.md). Verified dataset facts:
[`docs/data-notes.md`](docs/data-notes.md). Every experiment:
[`docs/experiments.md`](docs/experiments.md) (append-only). Every submission:
[`submissions/log.md`](submissions/log.md) (append-only).

- `wiki/`, `analysis/` — generated by wikikit, gitignored, **never hand-edited**. Entry points:
  `wiki/index.md`, `analysis/nb_priority.md`, `wiki/notebook-catalog.md`. Cleaned competitor

- `oof/` — member OOF and test arrays (gitignored).
- `submissions/` — submission CSVs (gitignored) plus `log.md` (tracked).

| --- | --- |
| Kaggle handle | `dougsgrott` |
| Train | 691,369 rows × 12 features + `id` + `addicted_label`; positive rate 0.7094 |
| Test | 296,302 rows |
| Public LB | 20% of test = 59,260 rows. Private = 237,042 rows |
| Submissions | 10 per day; **2** final selections |
| Numeric columns (9) | `age`, `daily_screen_time_hours`, `social_media_hours`, `gaming_hours`, `work_study_hours`, `sleep_hours`, `notifications_per_day`, `app_opens_per_day`, `weekend_screen_time` |
| Categorical columns (3) | `gender` (Female/Male/Other), `stress_level` (High/Low/Medium), `academic_work_impact` (No/Yes) |
| Missingness | All 12 columns have NaNs, at rates that differ between train and test in every column |
| Budget identity | `daily_screen_time_hours >= social_media_hours + gaming_hours + work_study_hours` holds in 100.000% of all 859,029 train+test rows |

**The frozen fold contract.** The entire public OOF ecosystem — and this repo — uses

```python
StratifiedKFold(n_splits=5, shuffle=True, random_state=42).split(train, train.addicted_label)
```

over `train.csv` in **original file row order**. OOF and test arrays are stored **positionally**
with no `id` column: `oof/oof_<name>.npy` has 691,369 entries in train order, `oof/test_<name>.npy`
has 296,302 entries in test order. `data/folds.npy` is the materialised assignment; regenerate it
with `scripts/make_folds.py`, never inline.

## Non-negotiables

1. **Folds are frozen.** Every member trains on `data/folds.npy` and exports the positional OOF
   contract above. A member that cannot produce an aligned OOF array cannot enter a stack.
2. **No final submission is selected on public-LB score alone.** The public split is 59,260 rows;
   two correlated submissions differing by less than **~7e-05** are not distinguishable on it, and
   three of the seven finished Season-6 boards erased their entire public top ten. Pick finals on
   nested CV. Calibration: **nested honest CV ≈ LB − 0.0011**.
3. **Any fitted blend weight goes through nested CV** — fit on 4 folds, score on the 5th. Naive
   full-OOF weight fitting reports a premium that does not exist out of sample.
4. **No claimed gain below the noise floor.** ~1e-4 on CV; ~7e-5 on LB for correlated
   submissions, ~1.3e-3 for uncorrelated ones. Rank movement is not evidence: a change that moves
   40 places but moves the score by less than 1e-4 has measured nothing.
5. **Audit borrowed members for the level-2 trap.** A member whose own features are somebody
   else's level-1 OOF columns built on a different partition is row-honest but leaks through other
   rows' columns. It moves CV and LB in *opposite* directions. Filter any external manifest's
   `family` field on `stack|blend|ensemb|meta`.
6. **Public code is reusable and encouraged** (competition rules 2.6, 3.6.b) — everything in
   `analysis/nb_clean/` is public. Cite the source path when lifting something.

## Commands

Working today:

```bash
uv sync                                 # install/refresh the environment
uv run python scripts/make_folds.py     # -> data/folds.npy, the frozen partition (idempotent)
uv run python scripts/check_env.py      # gate: libraries, GPU, shapes, invariants — must PASS
uv run python scripts/benchmark.py      # real per-member training cost on this machine
uv run kaggle competitions leaderboard playground-series-s6e8 -s

```

Data download (the CLI has no `--unzip`; unzip separately):

```bash
uv run kaggle competitions download -c playground-series-s6e8 -p data/
(cd data && unzip -o playground-series-s6e8.zip && rm playground-series-s6e8.zip)
```

Built as the roadmap phases land — do not assume these exist yet:

```bash
uv run python scripts/train_member.py --model <name>        # Phase 2 -> oof/oof_<name>.npy + oof/test_<name>.npy

```

## Environment traps (measured 2026-08-26, see `docs/issues/001-phase-0-ground-truth.md`)

- **Pin `xgboost>=2.1,<3.0`.** The 3.x wheels are built against CUDA 13; this WSL driver provides
  CUDA 12.9, so 3.x **silently falls back to CPU** — a warning, not an error, and a 14× slowdown.
  `xgboost==2.1.4` trains on the GPU. Every member script must assert it got the device it asked
  for; do not trust `torch.cuda.is_available()` as a proxy for another library.
- **Cap OpenMP threads before importing lightgbm or xgboost.** The box has 20 cores but runs at
  load average ~50, so extra threads spin and contend: the same XGBoost fit took 2.0 s at 1 thread
  and 18.0 s at 4, and never finished at 20. Set `OMP_NUM_THREADS` / `OPENBLAS_NUM_THREADS` /
  `MKL_NUM_THREADS` (the `S6E8_THREADS` env var, default 2) at the top of the script, and pass a
  matching `n_jobs`. Prefer the GPU where the family supports it.
- **`nvidia-nccl-cu12` and `-cu13` share one install directory.** Removing either deletes the
  other's `libnccl.so.2` while leaving the package metadata intact, so `uv pip list` looks fine and
  `import torch` fails. Repair with
  `uv pip install --reinstall-package nvidia-nccl-cu12 nvidia-nccl-cu12==2.21.5`.
  Run `scripts/check_env.py` after **any** dependency change — it guards all of these.
- **Run long jobs with `PYTHONUNBUFFERED=1`.** Redirected stdout is block-buffered, so a job that
  is killed loses everything it printed and looks identical to one that never started.
- **Check `MemAvailable` before a long run.** Nominal RAM is 7.8 GB but only ~2 GB was actually
  free during Phase 0. The data is not the problem (271 MB as float32); careless copies are —
  never one-hot the full frame, use native categorical support instead.

## Working style

- CV is the referee for direction; ship no change without an OOF delta and a row in
  `docs/experiments.md` — negative results included.
- Establish the noise floor (repeated CV across partition seeds) before believing any ablation.
  Per-fold spread is not the noise floor and overstates it by roughly an order of magnitude.
- Prefer capacity before features: on this data `num_leaves` 15→31 was worth 18× the entire
  feature-engineering block, and it made those features worthless once applied.
- A new stack member must be **decorrelated AND comparably strong**. Rank correlation above ~0.99
  to an existing member, or more than ~0.006 AUC weaker, and it earns weight 0.000.
- After finishing a piece of work, output recommendations on how to proceed or which task to pick
  up next.

## Do not

- Do not commit or push to git. Editing the working tree is fine; `git add`, `commit`, `push`,
  `branch`, `checkout`, `merge`, `rebase`, `stash`, `reset` are the repo owner's. Read-only git is
  fine.
- Do not hand-edit anything under `wiki/` or `analysis/` — change the config or rerun the command
  that produces it.
- Do not edit the crontab directly; wikikit cron entries are managed via `wikikit cron`, and never
  installed or removed unasked.
- Do not run expensive validation just to verify a change — no full pipeline re-runs, no
  API-billed AI runs. Use cheap structural checks.
- Avoid writing in the first person; prefer third-person prose.
